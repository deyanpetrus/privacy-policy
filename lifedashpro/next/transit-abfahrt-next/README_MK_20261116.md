# LifeDashPro NEXT — Abfahrt! optional API bridge (2026-11-16)

## Verified provider terms
- Docs: https://www.abfahrt.now/docs/
- API: GET https://api.abfahrt.now/departures?lat=...&lon=...; `x-api-key` required.
- Free: **100 external requests/day, per key**, reset midnight UTC. API offer advertises free keys for hobby/personal use by emailing hi@abfahrt.now.
- For a public Google Play app, request written authorization from provider to use the free pilot and confirm commercial/display licensing; Terms prohibit redistribution of **raw** API data. Keep required provider attribution verbatim in every displayed screen.
- Coverage 28 countries; Spain/Madrid, HR/Zagreb and BG/Sofia appear on provider's coverage lists, but performance must be proven via real authenticated requests.
- Abfahrt is for station departures, delays, cancellations, platforms; it is **not** a roadwork, country-wide road alerts or service-bulletin feed.

## Installed Supabase foundation
Main project `djbxhyhqefylyqqlifan`.
- Additive function: `transit-abfahrt-next` V1 ACTIVE (JWT enabled), but **external provider access is disabled by default**.
- Allowed actions: `{action:"status"}` and `{action:"departures",lat,lon,radius?,mode?}`.
- Function reads secrets `ABFAHRT_API_KEY` and `ABFAHRT_API_ENABLED` (must be exactly `true`).
- Supabase Dashboard > Edge Functions > Secrets: set these only after permission for LifeDashPro is obtained. NEVER commit or paste the key in chat, GitHub, APK or client code.
- Shared service-role-only RLS tables `public.next_abfahrt_cache_v1` and `public.next_abfahrt_daily_usage_v1`.
- Postgres `public.reserve_next_abfahrt_free_v1()` is SECURITY INVOKER, EXECUTE for service_role only (authenticated cannot call). Atomic global 60/day budget across all users. This stays under provider free plan's 100/day and deliberately reserves margin.
- Cache TTL 10 minutes for exact lat/lon rounded to 0.001 degrees, radius and mode; returns up to 20 normalized departures and attribution. Expired departure timestamps suppressed on cache hits.
- Cron `lifedash-next-abfahrt-prune` cleans expired cache and old usage rows daily.
- No automatic polling. Existing transit providers unaffected. An upstream failure returns error; Android client must fallback rather than display fictional LIVE rows.
- Region-level `realtime:true` is **not** evidence every row is realtime. Client must show quality as provider-level and avoid overclaiming.
- Once key and permission are supplied, test first via authenticated app client; this pilot has NOT been exercised against Abfahrt live yet.
